# Changelog

Все значимые изменения проекта Melecho.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [1.3.0] - 2026-11-21

### Добавлено
- **Подсистема пакетных отчётов (Reports):**
  - Очередь выполнения операций по выбранным серверам (шаблоны в `profiles/<slug>/reports.d/*.yaml`, включены в перенос `.melecho`).
  - Последовательное выполнение операций внутри каждого сервера, параллельный опрос серверов (через `ops_sem`).
  - Конструктор отчётов и YAML-редактор с поддержкой drag-перестановки шагов со сдвигом (FLIP).
  - Модалка запуска с живым SSE-прогрессом (`report.progress`, `report.finished`) и кнопкой отмены.
  - Экспорт результатов в `CSV` (`utf-8-sig` с защитой от формульных инъекций), `JSON`, `Markdown` и `PDF` (через стили `@media print` без сторонних зависимостей) с выбором режима: `Display + сырой`, `Только display` или `Только сырой`.
  - Новый режим LLM-чата `/report` (`report`) для автогенерации YAML отчёта.
  - Подвкладка «Отчёты» в разделе «Автоматизация».
- **Markdown в ответах LLM:**
  - Двухуровневый парсер без `innerHTML` (Preact VDOM, строгий CSP): заголовки, списки со смешанной вложенностью, цитаты, таблицы, ссылки (`http/https`), инлайн-код и блоки кода.
  - Потоковый рендеринг незакрытых блоков во время генерации ответа.
- **Индикация размышлений LLM:** отображение переливающегося статуса «Модель размышляет…» при получении блоков рассуждений (`<thought>` и reasoning-полей) вместо застывшего текста.
- **Смена SSH-порта и сетевых параметров:** редактирование `Host / IP`, `Порт` и `ОС` уже добавленного сервера с автоматическим сбросом сессии, кэшей и защитой TOFU host key (S7).

### Исправлено
- Снято обрезание выпадающих списков режимов чата и профилей в плавающем окне (`position: fixed` с расчётом доступного пространства).
- Корректная отправка вложений в LLM при непустой истории чата в специализированных режимах.
- Устранено смещение влево при первичном появлении баннеров ошибок LLM.
- Транслитерация кириллических имён при скачивании файлов отчётов.
- Одноразовый sudo-пароль из отчёта больше не зависает в кэше сервера.

## [1.2.0] - 2026-11-17

### Добавлено
- **Детектор аномалий:** минимальный порог шума `min_sigma` per-metric для исключения ложных тревог на спокойных рядах; тумблер `detector_ignore_drops` (игнорирование спада нагрузки); секция «Детектор аномалий» в настройках.
- **Интерактивный граф автоматизаций:** подвкладка «Граф» в «Автоматизации»; визуализация всех элементов и их связей.
- **Потоковые операции (streaming):** поддержка `flags.streaming` и `max_duration_sec` (5..3600с), запуск бесконечных процессов (`ping`, `tail -f`) с мягким прерыванием SIGINT→SIGTERM→SIGKILL.
- **Декларативное форматирование `display:`:** поддержка режимов `kv`, `lines`, `table`, `sections` с парсингом regex/json для компактного вывода результатов операций; визуальный конструктор `UserOpDisplayBuilder`.
- **Сбор и хранение метрик per-server (миграция v19):** индивидуальные `metrics_interval_sec` (5..300с) и сроки хранения `retention_raw_days`/`retention_agg_days` (где `0 = вечно`), инкрементальный `run_downsample`, параллельный опрос серверов.
- **Карточка сервера и сервисы:** отображение причин аномалий (`public_server.anomalies`), кнопка `↗ Спросить LLM`, вкладка «Сервисы» с фильтрацией `all|allowed|active|failed` и быстрым перезапуском юнитов.
- **LLM-подсистема:** 3-попыточный retry с backoff при сбоях провайдера (429/500/502/503/504) с индикацией в UI, фильтрация и стриминг рассуждений `<thought>`/`reasoning_content`, гибкие настройки контекста `llm_context_*` (включая `0 = безлимит`), независимые окна и контекстное меню сообщений.
- **Современный стек HTTP:** миграция на `httpx2`.
- **Поддержка Docker (Linux и Windows via Docker Desktop):** добавлены `Dockerfile`, `docker-compose.yml`, `.dockerignore` и интерактивные лаунчеры `docker-menu.sh` / `docker-menu.ps1`; теперь можно запускать сервис из под windows!
- **Зашифрованные SSH-ключи профиля и авто-список:** безопасная загрузка ключей в `profiles/<slug>/keys/*.enc` (`AES-256-GCM` под DEK, права `0600`, перенос в архиве `.melecho`) и авто-список ключей из `~/.ssh`.

### Исправлено
- Баг в `ReactionEngine.update_rule`: объединение всех полей с текущими и принудительное выставление `action_policy="confirm"` для `dangerous` и `state_changing` операций.
- Защита от сжатия поля «Название» в длинных модалках (`flex-shrink: 0`).
- Очищены неиспользуемые импорты в тестах; тестовый набор расширен до 73 passed.

## [1.1.2] — 2026-10-19

Патч-релиз: критический фикс безопасности (S8) и приведение тестов
в зелёное состояние.

### Исправлено
- **S8: молчаливая генерация ключа аудита.** Если у существующего
  профиля (есть `encrypted_dek` в `settings`) пропадал файл
  `audit.key`, панель молча создавала новый. Это ломало HMAC-цепочку
  аудита без предупреждения. Теперь панель отказывается стартовать
  (`SystemExit`) с инструкцией восстановить ключ из резервной копии.
  Для «свежего» профиля (wizard) ключ по-прежнему создаётся штатно.

### Изменено
- **Покрытие тестами:** набор приведён к зелёному состоянию
  (`73 passed`).

## [1.1.1] — 2026-10-19

Патч-релиз: UX-фиксы механизма автообновления и установки ярлыка.

### Исправлено
- **Автообновление: экран «Melecho остановлен».** После успешного
  `apply_update` вкладка больше не висит с кнопкой «Обновляю…».
- **Автообновление: бейдж «доступно обновление».** После успешного
  `apply_update` кэш `~/.cache/melecho/update_available.json`
  сбрасывается: бейдж в шапке исчезает, повторная проверка не спамит
  GitHub.
- **Автообновление: текущая версия в UI.** Настройки → Обновления
  показывает «Текущая версия: X.Y.Z · канал установки: …».
- **Ярлык в меню: Exec.**
  Теперь путь берётся из
  `shutil.which("melecho")` или `<venv>/bin/melecho` (от
  `sys.executable`). Пути с пробелами корректно экранируются.
- **Ярлык в меню: KDE Plasma.** `_refresh_caches` теперь вызывает
  `kbuildsycoca6` / `kbuildsycoca5` — KDE хранит собственный кэш
  меню (sycoca), и `update-desktop-database` его не обновляет.

### Изменено
- **Строка версии в Настройках → Обновления.** Разделитель `·` между
  версией и каналом рендерится через `${' · '}` (явная JS-интерполяция),
  а не через перенос строки в htm — пробелы сохраняются корректно.

## [1.1.0] — 2026-10-19

### Добавлено
- Экспорт/импорт профиля: `.tar.gz.enc` с `app.db` (VACUUM INTO),
  `audit.key`, `manifest.json`, `dek.bin`; всегда шифруется

  только toggle в Настройках и явные флаги `--install-desktop` /
  `--uninstall-desktop`.

## [1.0.0] — 2026-10-16

Первый публичный релиз.

### Добавлено

**Ядро.**
- Локальная ИС управления Linux через SSH — без агента на серверах.
- HMAC-chain + signed head, ключ аудита вне БД (S2, S8).
- Argon2id v1 + AES-256-GCM, DEK, шифрование креденшелов и sudo-пароля.
- Терминал-агностичный POSIX-shell (`run_argv` через `/bin/sh -c`).
- CLI-лаунчер: детач через `Popen(start_new_session=True)`, attach
  через `SIGUSR1`, lock через `flock`, `--status` / `--stop` /
  `--install-desktop`.

**SSH.**
- Pre-fetch host key + pinning (S7), отказ без «продолжить».
- S7+ pre-flight host key на старте панели (фоновый probe).
- Все сценарии аутентификации: ключ без passphrase, ключ с passphrase,
  ключ + пароль (fallback), только пароль, keyboard-interactive.
- Редактирование `user` / `auth_type` / `credential` / `passphrase` /
  `key_path` в Настройках сервера.
- Auto-reconnect с backoff 5→10→20→40→60 с.

**Метрики и алерты.**
- CPU / RAM / Disk / Net / Load / Uptime, один SSH-exec на тик.
- EWMA + z-score (warmup 30 residuals), cross-severity, fingerprint-дедуп.
- Единая модель правил алертов: `alert_rules.condition_kind` (6 типов),
  7 builtin-правил.
- 6 типов: `metric_threshold`, `metric_zscore`, `metric_stale`,
  `operation_check`, `manual_op_failed`, `reaction_failed`.
- Reaction Engine: hardcode `confirm` для dangerous/state-changing,
  kill switch.
- Автосудо: 5 режимов, `disk` — зашифрован DEK, переживает рестарт.

**Различение «нет интернета» / «сервер недоступен».**
- TCP-handshake к настраиваемому хосту, флаг `internet_offline`.
- Флаг `servers.is_local` — локальные серверы работают при offline.
- Активный polling с backoff 5→10→20→30 сек.
- Баннер в шапке (4 состояния), countdown, ручная проверка.
- Блюр динамики карточки для внешних серверов при заморозке.

**LLM.**
- OpenAI-совместимый клиент, профили в БД, ключи шифрованы DEK.
- Стриминг `/llm/chat` (SSE), reasoning-фильтр.
- Suggest-стримы на SSE с построчным fence-парсером.
- LLM-команды: `/operation`, `/alert`, `/reaction`, `/explain`,
  `/explain-rule`, `/edit-rule`, `/help`.
- История диалога через `history`, изоляция режимов.
- Канарейки (S4), allowlist полей, opt-in на сырые логи (S5).

**UI.**
- Preact + htm без бандлера, Chart.js 4, вендорится локально.
- Двухуровневый скролл, кастомный скроллбар.
- Drag-n-drop карточек серверов и метрик (pointer events + ghost + FLIP).
- Панель метрик: batch-эндпоинт, per-metric окна, cutoff, per-server
  layout в localStorage.
- Плавающее окно LLM-чата.
- Баннер интернета в шапке, badge «доступно обновление».

**Инфраструктура.**
- Проверка обновлений: `detect_install_kind`, фоновый цикл, UI-секция,
  badge, автообновление для git-клона.
- Graceful shutdown: `SIGTERM` → `should_exit`, кнопка «Остановить и
  выйти» в UI.
- XDG-пути, pipx-установка, `.desktop`-интеграция.

### Инварианты

- S1: на управляемых серверах нет новых слушающих портов.
- S2: HMAC-chain + signed head, ключ аудита вне БД.
- S3: инъекции в параметры каталога блокируются (argv + whitelist).
- S4: секреты не уходят в LLM.
- S5: сырые логи не уходят в LLM по умолчанию.
- S6: Host / Origin / CSP / session-токен.
- S7: mismatch host key → отказ без «продолжить».
- S8: ключ аудита не в БД и не в `VACUUM INTO`.
